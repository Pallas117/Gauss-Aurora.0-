# Orchestrator: Local Decision Models and No Egress

This doc describes how the Gauss orchestrator connects to **localized decision models** (e.g. [MLX](https://github.com/ml-explore/mlx) on Apple silicon) and avoids egress of sensitive data by default.

## Principles (MLX-aligned)

- **Local-first**: Inference runs on device (127.0.0.1, MLX server, or Tailscale mesh 100.x.x.x). No dependency on external cloud APIs for core operations.
- **Unified memory / no egress**: Sensitive telemetry and mission reports stay on-host; decision-model URLs are allowlisted so cloud endpoints are never used unless explicitly opted in.
- **Air-gapped friendly**: Defaults match the [Project Gauss directive](../.cursor/rules/PROJECT-GAUSS-STRICT-OPTIMIZATION-DIRECTIVE.mdc): *"The code must not rely on external cloud APIs (AWS, OpenAI) for core operations. Default to 127.0.0.1 and Tailscale mesh IPs (100.x.x.x)."*

## How it works

### 1. Local / trusted URL allowlist

The orchestrator treats a decision-model URL as **local/trusted** only if its host is:

- `127.0.0.1`, `localhost`
- `::1`, `[::1]` (IPv6 loopback)
- `100.x.x.x` (Tailscale CGNAT range)

Any other host (e.g. `api.openai.com`) is **not** used for decision inference when strict-local mode is on.

- **Rust**: `gauss-orchestrator/src/local_only.rs` → `is_local_or_trusted(url)`.
- **Config**: `ORCHESTRATOR_STRICT_LOCAL_INFERENCE` (default: true).

### 2. Strict local inference (default: on)

- **Env**: `ORCHESTRATOR_STRICT_LOCAL_INFERENCE` (default true; set to `false`/`0` to allow cloud).
- **Effect**:
  - **Multi-agent**: Only the local engine (DeepSeek URL) is used for task routing and synthesis. GPT-4, Gemini, and Claude are **not** called when strict local is on, so no sensitive data is sent to cloud LLMs.
  - The local engine URL must pass `is_local_or_trusted()`. If you set `ORCHESTRATOR_LOCAL_ENGINE_URL` to a cloud URL while strict local is on, that URL is treated as disallowed and the engine is not used.

### 3. Daily mission summary: local by default

- **Env**: `ORCHESTRATOR_DAILY_SUMMARY_USE_LOCAL` (default true).
- **Effect**: The “Daily Mission Summary” is generated by POSTing to the **local engine** (`ORCHESTRATOR_LOCAL_ENGINE_URL`), not to OpenAI. No egress of report content.
- To use OpenAI for the daily summary instead, set `ORCHESTRATOR_DAILY_SUMMARY_USE_LOCAL=false` and provide `OPENAI_API_KEY`. This is opt-in only.

### 4. Pipeline triad (Surya → DeepSeek)

- Triad already uses `config.local_engine_url` for the DeepSeek step (no cloud in the default path).
- Ensure `ORCHESTRATOR_LOCAL_ENGINE_URL` points at your MLX server or gauss-brain-stub (e.g. `http://127.0.0.1:8088/v1/chat/completions` for MLX, or 8089 for stub).

## Env summary

| Env | Default | Purpose |
|-----|---------|---------|
| `ORCHESTRATOR_LOCAL_ENGINE_URL` | `http://127.0.0.1:8089/v1/chat/completions` | Local decision model (MLX / stub). |
| `ORCHESTRATOR_STRICT_LOCAL_INFERENCE` | `true` | Only allow local/trusted URLs for inference; no cloud egress. |
| `ORCHESTRATOR_DAILY_SUMMARY_USE_LOCAL` | `true` | Use local engine for daily summary; no OpenAI egress. |
| `ORCHESTRATOR_CLOUD_ENABLED` | `false` | Enable cloud routing for LOW/UNKNOWN telemetry (opt-in). |

## Wiring MLX

1. Start the MLX server (e.g. DeepSeek-R1-Distill-Qwen on port 8088):
   - From repo root: `npm run dev:brain:mlx` or run `scripts/process/run-mlx-deepseek.sh`.
2. Set in `.env` (or env):
   - `ORCHESTRATOR_LOCAL_ENGINE_URL=http://127.0.0.1:8088/v1/chat/completions`
   - Leave `ORCHESTRATOR_STRICT_LOCAL_INFERENCE` unset (true) and `ORCHESTRATOR_DAILY_SUMMARY_USE_LOCAL` unset (true).
3. No OpenAI/cloud keys are required for core decision path or daily summary.
